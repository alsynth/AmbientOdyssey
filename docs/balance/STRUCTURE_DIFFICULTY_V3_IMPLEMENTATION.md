# Structure difficulty v3 experimental kit — 13 October 2026

This kit is a reversible configuration experiment, not a full pack import or a gameplay-balanced release. The latest source baseline is `performance/v049-visual-ecology-20261013` at `b387dc0`; the physical audit target is the installed **Ambient Odyssey v0.4.9 - Client Performance TEST** profile. Its current 332 physical JARs differ from the 328-pin original import: Remnant Bosses is already upgraded and four Ars additions are present. The roster and installed pin delta are recorded, rather than rebuilding from a stale source lock. Historical catalogue tiers are retained byte-for-byte in the imported input. Current generation, datapack load order and multiplayer behavior require Minecraft tests.

## Scope and installation

The kit contains `candidate/config/dungeon_difficulty/difficulty_v2.json` and the exact original file under `rollback/`. Apply the candidate only to a **cloned disposable profile**, with matching server config, while both are stopped. It replaces the inherited six-zone pilot; do not install both files under alternate guessed names. The JAR's actual config path is `config/dungeon_difficulty/difficulty_v2.json`. Keep the world's configs, addons, performance settings, quests and native boss configs otherwise unchanged. Restore the rollback file and restart to undo future-spawn rules. Already scaled mobs can retain saved modifiers; restore the copied save as well for a clean rollback.

Only explicitly approved Tier 0–6 entries with a current root resource, unambiguous resource content, biome dimension evidence and structure-set reference qualify. For a combat rule, the traversed pool-reference templates must additionally contain a compatible ordinary mob in a spawner or inline trial potential. Optional built-in packs, differing provider collisions, unresolved dimensions, conflicting tiers and unproven compatible encounters are held. Root presence and a placement reference do **not** prove generation. New v3 proposals, Geburah and Tier 7–9 remain held. Dimension conflicts preserve the user's original logical variants without creating unsupported rules. All Bastion layouts use one native ID. Vanilla/replacement entries are held when the binary evidence cannot establish separate active placement.

The candidate adjusts selected ordinary vanilla melee enemies: HP, attack and armor. T0–1 have no entity changes. T2–6 use additive-to-base HP bonuses of 10/20/30/40/50%, attack bonuses of 5/10/15/20/25%, and armor additions of 0.5/1/1.5/2/2.5. Each tier is a separate type at **DD level 1**, preventing accidental multiplication by tier number. These are experimental budgets, not permanent gameplay decisions. Projectile, explosion and spell damage may bypass attack attributes; creepers, evokers, vexes, ravagers, breeze and all modded IDs are excluded rather than claiming control over those mechanics.

Spawner multipliers, player-count difficulty, player effects, XP bonuses and automatic item/loot scaling stay zero/off. Population, delays, equipment, elites, trial spawners, vault rewards and boss mechanics have **not** been reauthored. Structures relying on those controls remain partial attribute pilots or held; they cannot be called fully tuned T6 encounters.

## Stacking gate

The installed DD 3.9.2 entity matcher has only `attitude` and `type`, with no boss-NBT filter. An elite using an ordinary vanilla entity ID can receive DD too. Global Brutal Boss multipliers of 1.0 do not remove per-boss definition bonuses; its installed chest spawn chance is 30. Apotheotic prototype behavior also needs encounter-specific testing. The kit's bounded base additions do not certify a final combined cap. **Promotion is blocked until elite stacking is measured or an addon provides a proven exclusion.** Never increase population or enable another party/global scaler to compensate. Named mod bosses are excluded by the exact vanilla allowlist, and no native boss stats change.

## Reproduction and evidence

Run the NBT census with `nbtlib==2.0.4`, then the builder:

```
python tools/audit_encounter_nbt_041.py --mods-dir <instance>/mods --out docs/balance/v3-evidence/ENCOUNTER_NBT.csv
python tools/structure_difficulty_v3.py --instance <instance> --vanilla-jar <exact-1.21.1-client.jar> --output <kit.zip>
python -m unittest discover -s tests -p test_structure_difficulty_v3.py
```

`INSTALLED_JARS.json` records SHA256, size and native metadata of each physical JAR, plus the vanilla resource input. `CURRENT_PROFILE.json` records current installed pins separately from the historical import manifest. `RECONCILED_CATALOGUE.csv` preserves every row and adds installed/archived/overridden/uncertain status, dimension evidence, placement leads and explicit hold reasons. `APPROVED_TIER_MAPPING.csv` includes all 282 approved 0–6 rows, including those held. `RESOURCE_COLLISIONS.json` lists differing providers without inventing precedence. The NBT census records spawners, trials, vaults and equipment indicators. `LOOT_TABLE_INDEX.csv` records current native table paths/provider hashes and holds container-role classification for the economy review. `TEMPLATE_RESOURCE_LINKS.csv` records exact serialized NBT string leads for pool and chest-table references. Pool traversal is an inspection lead: actual jigsaw connector selection, code-defined rooms and alternative palettes are not proven reachable. World-specific datapacks and dynamic registries remain runtime gates.

The audit finds root resources for all **386 named active candidates**: 351 unambiguous resource candidates, 33 with differing resource providers and two disabled vanilla replacements. The 41 reference rows remain archived. This establishes current binary resource presence, not effective registry/generation. **53 unique approved rules** qualify: 25 preserve natural behavior and **28 apply the limited ordinary-entity attribute pilot**. **374 rows are held**, including archived entries, new proposals, boss tiers, unresolved dimensions, overrides and unsupported/unproven compatible encounters. Aviary and Keep Kayra qualify at Tier6; Foundry and Mechanical Nest at Tier5; YUNG Nether fortress, IDAS Catacombs and Adventure Dungeons Trialrooms at Tier4. Sky/Ice remain approved Tier3 classifications but are held for native encounter controls. All ten Twilight IDs and native biome-source dimension membership are confirmed as resources; their code-defined/boss encounters lack compatible ordinary-target evidence in this census and remain held. The YUNG ocean monument remains held because not every eligible modded ocean biome has proven dimension membership. Explicit native Pasterdream biome-source membership is recorded while preserving original catalogue labels/tiers; compatible encounters still need to qualify. `ENCOUNTER_CONTROL_GAPS.csv` flags both partial pilots and candidate locations held for unproven compatible encounters.

The census covers **18,417 root mod templates**, with **18,415 decoded**, **2,805 templates with encounter/equipment indicators**, and two unreadable Archaion templates (`ancient_keep/misc_room.nbt`, `misc_room_x.nbt`). Reading a single compressed NBT root recovered 184 templates that failed strict gzip end-of-stream validation; the recovery record is retained and no JAR bytes changed. Across distinct template resources it found 1,979 ordinary spawner blocks, 396 trial-spawner blocks, 185 vault blocks and 5,928 equipment indicators. These are resource counts, **not generated encounter populations**. Inline trial mob potentials were refreshed in 178 templates. The loot index contains 15,163 provider/table records. One Dungeons & Taverns pool with a bare JSON identifier remains unsupported by this static parser; it is recorded without calling it a proven game crash. Both parser limitations require targeted runtime/effective-resource inspection.

The exact installed DD bytecode proves `value * level + offset` and the entity-filter limits. Upstream documentation describes structure→biome→dimension resolution, but its root config-path example is stale for the installed binary: [official source](https://github.com/ZsoltMolnarrr/DungeonDifficulty/tree/1.21.1). Current JAR evidence takes precedence.

## Compatibility and encounter editability

- WDA, Dungeons & Taverns, IDAS and Moog: root structure/pool/NBT and loot resources support targeted datapack authoring where present. Audit real room paths and spawned entities first; JSON presence alone does not prove equipped enemies. WDA Heavenly dimension conflicts are held.
- Pasterdream: native dimension JSON resolves several structures to `pasterdream:lamp_shadow_world` or `pasterdream:wind_journey_world`, with some entrances in Overworld. Qualified approved entries use these explicit per-structure results; other mixed/uncertain dimensions and special spawn mechanisms remain held or flagged. No blanket biome or namespace rule.
- Cataclysm, Integrated Cataclysm, Mowzie and Integrated BOMD: colliding parent/integrated paths are held pending effective pack precedence. Preserve the integrated arena; never patch a losing parent template. Maledictus remains only Frosted Prison, Tier 7, outside this kit.
- Twilight Forest: exact ten upstream IDs and biome-grid dimension resources are checked against physical root resources. Code-defined landmark mobs and boss mechanics prevent ordinary-target qualification in this pilot. Hydra Lair remains Tier 4 with no DD rule. Boss stages, progression locks, summons and immunity need native tests.
- Iron's Spellbooks: config controls some boss health/damage; spell damage and cast timing are separate. Nether structures require Nether evidence rather than the old display label.
- Incendium and major End dungeons: root resources and dimension biome tags are audited; datapack activation and code-only placement remain separate. Do not infer an End variant from the display name.
- Vanilla and custom trial chambers: DD's installed mixin list has ordinary `MobSpawnerLogicMixin`, no trial-spawner hook. Inspect `normal_config`, `ominous_config`, entity potentials, rewards and vault NBT; use native datapack overrides after exact routing is verified.
- Dungeon Crawl: existing AO deferred DD evaluation retries and pending-spawner-NBT fix are preserved. Re-test generated mobs; no claim that retries heal low-health mobs or fully tune equipment.
- Sky/Ice arenas: the installed `sky_arena.json` exposes spawn radii, point budgets, native stat multipliers, per-player statistics, common/elite/miniboss/boss mob groups, reward tables/counts and disabled mob-item drops. Sky's existing level ranges progress from common mobs at 1–10 to boss groups at 41–9999, with later stat increases. These are compatible ordinary mobs controlled by a **native wave scaler**, not fixed template spawners. Their Tier3 classification is preserved, but adding a DD rule would compound native wave progression and needs a separate per-wave budget. Native controls are captured in `SKY_ARENA_NATIVE_CONTROLS.json`; no arena or reward values change.

## Loot integration plan

Keep encounter tier separate from container role. Inventory table IDs and each container's reachable template/NBT before classifying supply, equipment, treasure or major completion reward. Use targeted native table overrides or supported loot modifiers; retain Lootr per-player access and independently test reward eligibility, restart and reruns. No economy values change here.

Build an economy ledger for rarity unlocks, affix/gem tiers, salvage, sockets, trade costs, summon costs, completion rewards and repeatable sources. Gate high Apotheosis rarities on approved progression; retain random armor trims. Goblin-Tuned modifiers stay intact while future documented price adjustments target repeatable trades. Avoid giving elite equipment through both death drops and completion containers. Measure loot per player-hour, per summon and per repeat clear; distinguish first clear from farmable rewards. Test vault key consumption, ominous rewards, Lootr multiplayer duplication and spawner farms before permanent values are approved.

## Runtime acceptance checklist

1. Clone profile and save; record JAR/config hashes and loaded datapacks. Boot full client and dedicated server; verify config parses and remains intact after reload.
2. Export loaded structure IDs and effective resource providers. Resolve all held replacements, builtin packs and parent/integrated arenas. Locate and naturally generate representative structures in every dimension; existing chunks alone do not test new placement.
3. In fresh T0/T1/T2/T4/T6 structures record ordinary mob base/final attributes, current health, equipment, arrows/spells, and DD state. Compare outside/inside boundaries, overlapping structures, spawn-time lookup, existing mobs and reload/restart. Test T7–9 named bosses and Geburah are unchanged.
4. Measure spawner delays/count/range, nearby limits and mobs alive; trials normal/ominous, vault keys/rewards, boss triggers/phases/resets/damage caps. Test natural generation as well as commands. Do not equate a template census with encounter execution.
5. Test ordinary mobs, Apotheosis elites and Brutal Boss variants separately and combined. Record all modifiers and combat damage. Establish a combined cap or implement proven exclusions before promotion.
6. Solo, two-player and 5–7-player runs with documented gear/skill: completion time, deaths, consumables, pacing, ranged pressure, save/restart and repeat rewards. Keep party scaler disabled until nearby participant semantics are proven.
7. Compare loot-role economy, affix/gem gating, trims, Goblin trades, boss drops and farming. Include each player's Lootr state and vault eligibility.
8. Compare baseline/candidate MSPT p95/p99, spawn/entity counts, cold/warm generation, memory and save/restart on the same seed. Preserve r19 rollback and performance branches.
